# task backlog

Asana のバックログをモデルにした、ローカル完結のタスク管理ツール。

## 起動

サーバー（`server.py`）はログイン時に裏で自動起動しています（下記）。
ボードを開くときは `start.bat` をダブルクリックするだけです。

**接続やファイル選択の操作はありません。** 保存は `server.py` が受け持ち、
編集の 0.5 秒後に `tasks.json` へ書き込みます。左上が緑の「tasks.json に自動保存」
なら書けている状態です。

### ログイン時の自動起動（2026-10-02 から）

スタートアップフォルダの `taskboard server.lnk` が、ログインのたびに `pythonw` で
`server.py --no-browser` をウィンドウなしで起動します。ボードは
`http://127.0.0.1:8777/index.html` を開くだけで使えます。

- `start.bat` を押したときにサーバーがもう動いていれば、ブラウザを開くだけにする（二重起動しない）
- 止めたいときはタスクマネージャーで `pythonw.exe` を終了する
- 自動起動をやめたいときは、`shell:startup` を開いて `taskboard server.lnk` を消す

`index.html` を直接ダブルクリックした場合はサーバーがいないので、ブラウザ内保存
（localStorage）だけになります。その場合に限り、サイドバー上部から `tasks.json` を
選ぶ操作（File System Access API）が使えます。**通常は start.bat から開いてください。**

## データの保存先

同じフォルダの `tasks.json` ひとつです。中身はただのテキストなので、コピーすれば
それがバックアップになります。

`server.py` は保存のたびに `backups/` へ日付つきの控えを取ります（最短1時間おき、
最大40世代）。控えは書き換える前の内容なので、間違えたときはそこから戻せます。
書き込みは一時ファイル経由で差し替えるので、途中で落ちても `tasks.json` が
半端な状態になりません。

保険として、すべての変更はブラウザ内（localStorage）にも複製されます。
`tasks.json` より新しい未保存の変更があれば、起動時に確認されます。

## 構造

Slack リスト「task backlog_たけしま」の作りに合わせてあります。

| Slack リスト | このツール |
| --- | --- |
| 領域（アプリ / SEO / WM / オウンド / その他） | プロジェクト |
| ステータス（未着手 / タスク化 / 進行中 / リリース待ち / 完了） | セクション |
| 名前 | タイトル |
| 期限日 | 期日（サブタスクにも持てる） |
| アウトプット | 参照リンク（URL のとき）／メモ（それ以外） |
| 子レコード | サブタスク |

### 完了の扱い

完了にすると「完了」の区切りへ移ります。**完了の区切りだけは中身を常に出す**ので、
カードが完了列に移るのが見えます。どこかへ消えることはありません。

「完了も表示」は、完了の区切り以外に居る完了タスクを出すかどうかの切り替えです。

画面上部のチップとサイドバーの数字は、どちらも「まだ終わっていない件数」です。
完了列の件数はその列の見出しに出ます。

**セクションとステータスは連動します。** セクション名がステータス名と同じ
（＝Slack のボード列と同じ使い方）のとき、ステータスを変えるとそのセクションへ
移動し、セクションへドラッグするとステータスが変わります。まだ無い列は
その時点で正しい位置に作られます。

自分で作った任意名のセクション（例「あとで見る」）は連動の対象外です。
そこに置いたタスクはステータスを変えても動きませんし、そこへドラッグしても
ステータスは変わりません。

## ビュー

右上で「リスト」「ボード」「週」を切り替えます。選んだ方は次回も保たれます。
どちらも同じデータを見ているだけなので、片方での変更はもう片方にも出ます。

- リスト … セクションを見出しにした縦一列。全体を見渡すとき
- ボード … セクションを列にしたカンバン。カードをドラッグして列を移動できる

ボードの列はセクションです。列名がステータス名と同じなので、**カードを別の列へ
ドラッグするとステータスも変わり**、列の下の入力欄から足したタスクは
その列のステータスで作られます。

### 週（カレンダーに時刻を置く）

左に「時刻が未定のタスク」、右に日〜土の週カレンダーが出ます（Sunsama 型）。
置く単位は最小のタスクです。サブタスクがあるタスクはサブタスクが1件ずつ出て、親は出ません。

- 左のタスクを右へドラッグすると、その日時に置かれる。長さは工数（未設定なら 1h）
- 置いたブロックはドラッグで動かせる。左へ戻すと時刻が外れる
- 左の「この週にやる」は、タスク化・進行中・リリース待ちのもの。未着手は下に畳んである
- 灰色は Google カレンダーの会議。破線のブロックはまだカレンダーに反映していないもの

**週カレンダー上部の「Claude に同期を頼む」ボタン**（2026-10-02）で、`server.py` が裏で
Claude Code（コマンド版 `claude -p`）を起動し、`taskboard-sync` を実行します。1〜2分で終わり、
結果がボタンの下に出ます。裏の Claude に許すツールは `server.py` の `Sync.TOOLS` に限定してあります
（カレンダーの読み書き、Slack の読み取り、`calendar_sync.py` / `inbox_sync.py`、`sync_tmp/` への書き込み）。
最後の結果は `sync.log` に残ります。コマンド版 Claude のログイン先組織に、Google カレンダーと
Slack のコネクタがつながっている必要があります。

**Google カレンダーへの反映は Claude が受け持ちます。** 「カレンダー同期して」と頼むと、
スキル `taskboard-sync` が `calendar_sync.py` を使って予定を作り・動かし・消し、
会議とカレンダー側の変更を `calendar.json` に書きます。画面は calendar.json を読むだけです。
カレンダーで予定を動かすと、次に同期したあとボードの時刻も動きます。

gcloud の認証ではカレンダーの権限が Google にブロックされるため、画面から直接は書けません。

### inbox（思いついたタスクの仮置き場）

サイドバーのいちばん上。Slack の自分宛てDMで、1行目を「タスク」にして送ると、
2行目以降が1行1件で入ります。工数や期日は書かなくてよいです。

```
タスク
CPP文言見直す
```

拾うのは Claude の同期（`taskboard-sync`）のときです。`inbox_sync.py` が `inbox.json` に書き、
画面はそれを読んで取り込みます。画面の入力欄から直接足すこともできます。

各項目でプロジェクト・親タスク・期日・工数を選べます。

- 「移す」… プロジェクトの「未着手」に入る。親タスクを選んでいればそのサブタスクになる。分解が要るものはこちら
- 週ビューの左のバーにも inbox が出ていて、**そのままカレンダーへドラッグできる**。突発の軽いタスク向け。
  置いた時点でプロジェクトの「タスク化」に入る（未設定なら「その他」）。期日が空なら置いた日になる

### すべてのタスク

プロジェクトをまたいで、同じ名前の区切りを1つに束ねて見せます。並びは
未着手 → タスク化 → 進行中 → リリース待ち → 完了 で、ボードではこの5列を
（そのプロジェクトにまだ無くても）必ず出します。リストでは中身が無い区切りは
出しません。各タスクにはどのプロジェクトのものかが小さく添えられます。

このビューでも区切りをまたいでドラッグできます。**プロジェクトは動きません** ―
移した先と同じ名前の区切りが自分のプロジェクトに作られて、そこに入ります。
プロジェクトの付け替えは詳細パネルからやってください。

追加欄にはプロジェクトの選択が付いています。どこに足すか選んでから打ってください
（選んだプロジェクトは記憶され、全部の区切りの追加欄で共通です）。

カードの名前はその場で打ち替えられます。カードは名前の欄以外のどこを持っても
ドラッグでき、名前の欄を押したときはドラッグが始まらないので、カーソルを置いて
編集できます。Enter か、ほかをクリックすると確定します。

## 画面でできること

取り込みのあとは、すべてこの画面だけで完結します。JSON を落としてくる作業は
もう不要です。

- タスク … 追加 / 名前の編集（リストの行・ボードのカードに直接打てる）/ 完了 /
  削除（取り消し可）/ ドラッグで並べ替え
- サブタスク … 追加 / 完了 / 期日 / 削除 / **ドラッグで並べ替え**（詳細パネル内。
  行の左に出る掴み手からドラッグする。一覧の余白に落とすと末尾へ）
- セクション … 追加 / 名前変更 / 上下の並べ替え / 削除（`⋯` から。ボードの列見出しからも）
- プロジェクト … 追加 / 名前変更（見出しをクリック）/ 上下の並べ替え / 削除
  （サイドバーの `⋯` から。削除するときは中のタスクの移動先を選ぶ）

プロジェクト間でタスクを移すと、移動先の「同じステータスの列」に入ります。
ステータスは書き換わりません。

## Slack リストの取り込み

Slack でリストを開き `⋯` →「ダウンロード」。

書き出した **JSON をそのまま画面にドラッグ＆ドロップ**してください。列の割り当て
画面が出ます（列の型から自動で当たるので、たいていそのまま「取り込む」でよい）。
CSV でも同じですが、CSV にはサブタスクの期日が入らないので JSON を推奨します。

「▼」で始まる見出し行と、タイトルが空のレコードは除外されます。
プロジェクト列を割り当てると値ごとにプロジェクトが作られ、セクションを空に
しておくとステータスと同じ名前のセクションに入ります。

同じことをコマンドラインからもできます（結果は画面のドラッグと同一）:

```
python import_slack_list.py <ダウンロードした.json>
```

### 接続について

初回だけ、サイドバー上部から `tasks.json` を選ぶ操作が要ります。ブラウザは
ページが勝手にディスクのファイルを書き換えることを許していないためで、
以降は自動保存になります（詳しくは上の「データの保存先」）。

未接続のまま編集していた分がある状態で接続すると、どちらを残すか聞きます。
「OK」で画面の内容を `tasks.json` に書き込み、「キャンセル」でファイルの内容を
読み込みます。黙って上書きすることはありません。

### 接続先を間違えないこと

サイドバー上部の「接続」で選ぶのは、必ず `taskboard` フォルダの `tasks.json` です。
Slack の書き出しファイルなど別の JSON を選ぼうとすると、警告を出して接続を
拒否します（そのまま接続できると、次の保存でそのファイルを壊してしまうため）。
いま何に接続しているかは、サイドバー上部のファイル名で確認できます。

## データ構造

`tasks.json`

```
projects[]  id, name, sections[]{id, name}
tasks[]     id, projectId, sectionId, title, notes,
            status(todo|ticketed|doing|release|done),
            priority(''|high|mid|low), due(YYYY-MM-DD), url,
            subtasks[]{id, title, done, due},
            schedule{date, start(HH:MM), setAt} | null,
            createdAt, completedAt, order
```

`calendar.json`（calendar_sync.py だけが書く）

```
syncedAt, range{from, to}, events[]{title, allDay, start, end},
links{taskId: {eventId, date, start, end, syncedAt, gone?}}
```

並び順は `order`（数値、昇順）。ドラッグで前後の中点が入ります。
Slack リストに優先度の列はないので、取り込んだタスクの優先度は空です。

## 設定（2026-10-02）

左下の「設定」から開きます。保存先は `tasks.json` の `settings` で、どのブラウザで開いても同じになります。

- 名前 … 左上とブラウザのタブに出る（20文字まで）
- アイコン … 絵文字か画像。画像は正方形に切り抜いて 128px に縮めて保存。背景色も選べる。タブのアイコン（ファビコン）にも出る
- テーマ … システムに合わせる / ライト / ダーク
- カレンダーの表示時間帯 … 週カレンダーの縦軸（4時間以上）

## 見た目

フォントはハタラクティブのロゴガイドライン v3.0 の推奨に合わせています（2026-10-02）。
欧文・数字が Montserrat、和文が Noto Sans JP で、どちらも Google Fonts から読んでいます。
ネットワークが無い環境では落ちてこないので、その場合は Segoe UI / Yu Gothic UI になります。
読み込みを避けたいときは `<head>` の `fonts.googleapis.com` の行を消してください。

ボードのカードの高さは `.card` の `min-height` と `padding` で決めています。

## 工数

タスクとサブタスクに工数（時間）を持たせています。**0.25h（15分）刻み**で、
入力すると自動で丸まります（`0.4 → 0.5`、`1.3 → 1.25`）。刻み幅は
`index.html` の `EST_STEP` 1箇所で決めているので、変えたいときはそこだけ。

サブタスクがあるタスクは、**親の工数はサブの合計で固定**です（読み取り専用）。
未設定のサブが残っていると「3h　サブタスクの合計・未設定 2 件」と出ます。
サブがないタスクは親に直接入力します。

行とカードには `3h` のバッジ、ボードの列見出しには `進行中 4 · 6.5h` のように
合計が出ます。

期日は着手日として使う運用です（カレンダーに積むときの基準日になります）。

## 色

プロジェクトとセクションに色を持たせています。Slack リストの色の割り当てを
そのまま引き継いでいます（SEO=pink、アプリ=gray、WM=indigo、オウンド=green、
その他=brown、未着手=pink、タスク化=indigo、進行中=cyan、リリース待ち=green、
完了=gray）。Slack が持っているのは色名だけなので、実際の色味はこちら側の定義です。

色はサイドバーの四角、区切り／列の見出しの点、横断ビューのプロジェクト名に出ます。
変えるときは、プロジェクトかセクションの `⋯` メニューから選んでください。
取り込み時も Slack 側の色名を拾います。

## 絞り込み

画面上部のチップと検索は、**次回の起動には持ち越しません。** 毎回「すべて」で
開きます。絞り込んだまま閉じてしまうと、次に開いたときタスクが消えたように
見えるためです。

絞り込みで何かが隠れているときは、チップの下に「○○で絞り込み中。N 件が
隠れています」と出て、そこから解除できます。

## Git 管理

リモートは `https://github.com/leverages-takeshima-naoya/taskboard`（private）。
載せるのはコードだけで、データ（`tasks.json`・`calendar.json`・`inbox.json`・
`backups/`・`sync.log`・`sync_tmp/`）は `.gitignore` で外しています。
GitHub はデータのバックアップにはなりません。

`githooks/pre-commit` が、`.json`・`.log`・`backups/`・`sync_tmp/` がコミットに
入っていたら止めます。別の PC で clone したときは、最初に一度だけ有効にしてください。

    git config core.hooksPath githooks
